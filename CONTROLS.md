# Controls

The mapping below was drafted by the practice on 2026-10-19 from steering's docs/control-map.md and the standards named; it is an ARGUED mapping, not a certification claim. The frameworks are outcome-level; the sub-outcome codes are the practice's reading of them.

| Check | NIST AI RMF | ISO/IEC 42001 | OWASP Agentic Top 10 (2026) | EU AI Act | Why |
| :- | :- | :- | :- | :- | :- |
| (a) rows: every line is a well-formed projected row | GOVERN 1.5 | 7.5 Documented information; A.6.2.8 AI system recording of event logs | ASI10 Rogue Agents | Art. 12(1) | every governed run leaves an automatic, well-formed record over the system's lifetime; an agent run with no row is the rogue the inventory would miss. |
| (b) rows: every delivered row has a pull-request pr_url | MANAGE 4.1 | A.6.2.6 AI system operation and monitoring; 9.1 Monitoring, measurement, analysis and evaluation | ASI05 Unexpected Code Execution | Art. 12(2)(c) | a delivery exists only as a reviewable pull request, never as code that ran into main; the deployer can monitor what was changed and by which run. |
| (c) rows: resumed runs counted, not failed | MEASURE 3.1 | 10.2 Nonconformity and corrective action | ASI08 Cascading Failures | Art. 12(2)(a) | a resumed run is a contained failure kept visible as a second row, not collapsed into a clean story; the situations that may present risk stay identifiable. |
| (d) packet &lt;id&gt;: provenance and ledger rows match rows/, and pr_refs.txt and provenance runs[].pr_url agree with the packet rows | MEASURE 2.8 | A.7.5 Data provenance; A.6.2.8 AI system recording of event logs | ASI09 Human-Agent Trust Exploitation | Art. 12(2)(b) | the evidence packet, the ledger and the PR reference agree with each other, so a reader trusts the record, not the agent's report of itself; this is the post-market monitoring data. |
| (e) packets: SHA256SUMS covers every packet file and every sum matches | MEASURE 2.7 | 7.5.3 Control of documented information | ASI04 Agentic Supply Chain Vulnerabilities | Art. 12(1) | packet bytes are hash-covered; a changed byte anywhere fails the gate, so the record's integrity holds over its lifetime. |
| (f) session &lt;id&gt;: trace and evidence records parse, every trace's decision matches the audit verdict, RESULT.md records the packet verifier's exit | MANAGE 2.4 | 9.2 Internal audit; A.6.2.6 AI system operation and monitoring | ASI02 Tool Misuse and Exploitation | Art. 12(2)(a) | a vendor session's actions are judged by a trusted-host audit after the fact (containment, gate, mutation, connector scan); a deny verdict is recorded as a deny, and the mapped decision cannot disagree with it. |
| (g) sessions: SHA256SUMS covers every source/ file and every sum matches | MEASURE 2.7 | 7.5.3 Control of documented information | ASI04 Agentic Supply Chain Vulnerabilities | Art. 12(1) | the vendor-run source files are hash-covered exactly as packets are. |
